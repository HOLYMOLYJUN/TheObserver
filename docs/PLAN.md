# TheObserver — 기획서

관심 기업의 **개발 직군 채용공고**가 사람인·잡코리아에 올라오면 Slack으로 알려주는 봇.
GitHub Actions에서 돌기 때문에 **내 컴퓨터가 꺼져 있어도 작동한다.**

---

## 1. 요구사항

| 항목 | 결정 |
|---|---|
| 감시 대상 | 지정한 18개 기업 (계속 추가 예정) |
| 수집 소스 | 사람인, 잡코리아 (2곳만) |
| 대상 직무 | 개발 관련 전부 — 웹 / 기획 / 앱 / 프론트 / 백 / 풀스택 |
| 알림 채널 | Slack Incoming Webhook, **카드형(Block Kit)** |
| 알림 주기 | 매일 **09:00 / 17:00 (KST)** 2회 |
| 실행 환경 | GitHub Actions (public repo → Actions 무료) |
| 언어 | TypeScript (Node 20+) |

---

## 2. 아키텍처

```
GitHub Actions cron (00:00 / 08:00 UTC = 09:00 / 17:00 KST)
  │
  ├─ 소스별 수집 (독립 실행, 하나 실패해도 나머지 진행)
  │    ├─ 사람인  : 공식 오픈 API (JSON)  ──실패시──▶  웹 파싱
  │    └─ 잡코리아: HTTP + cheerio 파싱   ──실패시──▶  Playwright(헤드리스 크롬)
  │
  ├─ 정규화       모든 소스를 공통 Posting 타입으로
  ├─ 회사 매칭    companies.json 의 별칭/회사코드로 대조
  ├─ 직무 필터    개발 관련 키워드 (include/exclude)
  ├─ 중복 제거    data/seen.json 대조
  ├─ Slack 발송   Block Kit 카드
  └─ 상태 커밋    data/seen.json 를 리포에 push
```

### 수집 우선순위

브라우저는 **최후의 수단**이다. 느리고(40배), 메모리를 먹고, 헤드리스 시그널 때문에
오히려 봇 탐지에 더 잘 걸린다. 목록 페이지는 대개 서버 렌더링이라 HTTP 요청이면 충분하다.

| 순위 | 방식 | 소요 | 용도 |
|---|---|---|---|
| 1 | 사람인 공식 API | ~1초 | 사람인 기본 경로 |
| 2 | HTTP + cheerio | ~2초 | 잡코리아 기본 경로 |
| 3 | Playwright | ~40초 | 위가 실패했을 때만 |

## 4. 안전장치

"조용히 죽는 것"이 유일한 진짜 실패 모드다. 알림이 없을 때
*공고가 없는 건지 / 봇이 죽은 건지* 구분할 수 없기 때문.

| # | 위험 | 대응 |
|---|---|---|
| 1 | 60일 무활동 시 GitHub이 스케줄 자동 해제 | `seen.json` 자동 커밋으로 리포 활동 유지 |
| 2 | 봇이 죽었는데 눈치 못 챔 | **월요일 오전 하트비트** — 신규 0건이어도 "정상 작동 중" 발송 |
| 3 | 예외 발생 시 침묵 | 크래시하면 Slack 🔴 에러 카드 + Actions 실패 처리 |
| 4 | 소스 하나가 전체를 죽임 | 소스별 독립 실행. 잡코리아가 막혀도 사람인은 발송 + 경고 첨부 |
| 5 | 첫 실행 알림 폭탄 | **부트스트랩 모드** — 최초 1회는 조용히 등록만, 요약 1건만 발송 |
| 6 | `seen.json` 무한 증가 | 90일 지난 항목 자동 정리 |
| 7 | 과다 발송 | 1회 실행당 알림 상한 (기본 20건), 초과분은 요약 |

## 5. 알려진 제약

- **GitHub Actions cron은 정시에 오지 않는다.** 혼잡 시 10~30분 지연되거나 건너뛴다.
  하루 2회 공고 알림에는 무해하다.
- **러너 IP는 Azure 데이터센터 대역**이라 차단될 수 있다. 저빈도(하루 2회)라 가능성은
  낮지만, 막히면 실행 위치를 Cloudflare Workers Cron 등으로 옮긴다 (컴퓨터 꺼져 있어도
  되는 조건은 유지됨).
- **사람인 API는 1일 500회 한도.** 하루 2회 실행이라 여유가 압도적이다.
- 사람인/잡코리아에 올리지 않고 자사 채용페이지만 쓰는 공고는 잡히지 않는다.

## 6. 크롤링 범위에 대한 원칙

CAPTCHA 우회 · 프록시 IP 로테이션 · 봇 탐지 회피는 **넣지 않는다.**
도덕적 이유가 아니라 **그런 게 도구를 더 잘 망가뜨리기 때문이다.**
차단 회피는 군비경쟁이라 상대가 룰을 바꾸면 새벽에 알림이 조용히 죽는다.

참고로 잡코리아가 사람인을 크롤링으로 제소해 승소한 판례(서울고법, 대법원 확정)가 있으나,
문제가 된 행위는 **대량 복제 + 자사 사이트 재배포 + 상업적 경쟁**이었다.
이 도구는 하루 2회 조회해 **본인 Slack에 링크를 던질 뿐**이며 재배포가 없다.
트래픽도 사람 한 명이 브라우징하는 것보다 적다.
